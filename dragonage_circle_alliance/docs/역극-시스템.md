# 캐릭터 역극 시스템

## 구현 범위

기존 Google 세션, 캐릭터 소유권, 포트레잇, R2 이미지 변환, 내부 알림, WebSocket 연결을 재사용한다. 기존 댓글·게시글·관계·호감도 레코드는 변경하지 않는다. 역극 작성이나 횟수가 관계와 호감도를 자동으로 바꾸지 않는다.

- **자유 타임라인:** 캐릭터 또는 OOC 작성, 원글별 대화, 답글에 답글, 작성 시각, 최근 활동/최신 작성 정렬, 수정·소프트 삭제.
- **장면:** 제목·상황·장소·참여 캐릭터·대표 이미지, 열람 범위와 참여 방식을 별도로 지정, 진행·중단·종료·보관, 재개, 참여·초대.
- **작성:** 줄바꿈, 굵게·기울임·인용·구분선, 안전한 미리보기, 이미지 최대 10장, Ctrl+Enter 전송. HTML을 실행하지 않는다.
- **임시 저장:** 기기 로컬 저장소에 회원·캐릭터/OOC·원글/장면·답글 대상·수정 대상별로 분리한다. 이미지 업로드 경로도 저장하고, 전송 성공 후 해당 초안만 지운다. 재시도는 같은 전송 식별자를 사용해 중복 등록을 막는다.
- **기록:** 캐릭터 프로필의 역극 기록 탭, 상대 캐릭터·상대 진영·진행 상태·자유 역극·답글 필터, 관계 상세의 공통 기록. 세 명 이상이 참여한 장면도 공통 기록에 포함한다.
- **검색/보관:** 제목·본문·장소·등장 캐릭터·진영·작성 기간, 진행/보관 메뉴, 오너 발언 숨기기, 날짜 구분, 대화 50개씩/타임라인 20개씩 페이지 표시, 텍스트·HTML 내보내기.
- **알림/읽음:** 기존 내부 알림함에 답글·멘션·초대·장면 새 글 알림. 전체/내 글 답글/멘션·초대/끄기 설정, 장면·대화별 읽음 기록.
- **실시간:** 기존 WebSocket에 역극 변경 신호만 추가했다. 활성 연결에서는 주기적 조회가 없다. 연결이 끊겼을 때만 역극 화면이 보이는 동안 15초 간격으로 변경분을 확인한다. 새 글 때문에 자동으로 스크롤하지 않는다.

## 데이터와 권한

신규 마이그레이션은 `migrations/0005_roleplay.sql`이다. 기존 테이블을 삭제하거나 재생성하지 않는다.

- `rp_scenes`: 장면 설정과 참여/허가 운영자 목록.
- `rp_messages`: 원글·답글·장면 메시지, 불변 작성 캐릭터 ID와 당시 이름·진영, 버전, 첨부 목록, 회원별 고유 전송 식별자.
- `rp_assets`: 기존 uploads/R2 경로를 해당 장면의 열람 권한에 연결한다.
- `rp_changes`: 자동 증가 커서로 변경 내용을 200건씩 동기화한다.
- `rp_preferences`: 회원별 역극 알림 설정.
- `rp_reads`: 회원별 장면/대화 읽음 기록.

이미지 원본은 기존 `uploads`와 R2에, 메시지 수정·삭제 이전 상태는 기존 `history`에, 알림은 기존 `notifications`에 보관한다. 소프트 삭제한 원글의 답글과 종료된 장면의 메시지는 보존된다. 최고 관리자의 기존 변경 이력/복구 기능에서도 역극을 처리하되 비공개 장면의 허가 여부를 확인한다.

매 요청에서 기존 로그인 세션을 검증한다. 캐릭터 발언은 서버에서 해당 캐릭터의 소유자와 장면 참여 여부를 검사한다. 발언 후 작성 캐릭터와 스레드는 변경할 수 없다. 메시지는 작성자만 수정할 수 있고, 작성자 또는 열람 권한이 있는 운영자가 삭제할 수 있다. 장면 설정은 생성자 또는 열람 권한이 있는 운영자가 관리한다. 참여자는 다른 캐릭터를 초대할 수 있다.

참여자 전용 장면은 생성자·참여 캐릭터 오너·참여한 OOC 오너·장면 설정에서 명시적으로 허가한 운영자만 열람한다. 운영자 등급만으로 모든 비공개 장면을 열람하지 못한다. 이미지 주소, 장면 이력, 내보내기에도 같은 검사를 적용한다. 단, 기존 최고 관리자/별도 백업 토큰의 전체 DB 백업 권한은 유지한다.

클라이언트는 열람할 수 없게 된 장면과 이미지 캐시를 즉시 지운다. 초대로 새로 보이는 장면의 과거 대화는 별도 100건 커서 페이지로 불러온다. 전체 이미지를 미리 내려받지 않고 실제 페이지에 보이는 이미지만 요청한다.

## API

모든 경로는 기존 `/api` 세션과 Origin 검사를 통과해야 한다.

- `GET /api/roleplay/sync?cursor=…&scenes=…`: 접근 가능한 장면, 변경 메시지, 다음 커서, 새로 열람 가능해진 장면, 본인 읽음 기록.
- `GET /api/roleplay/scenes/:id/history?after=…`: 해당 장면의 메시지 100건과 다음 커서.
- `POST /api/roleplay/scenes`: 장면 생성/설정 변경. 변경 시 id·revision 필요.
- `POST /api/roleplay/scenes/:id/join`: 공개 참여 장면에 본인 캐릭터 또는 OOC로 참여.
- `POST /api/roleplay/scenes/:id/invite`: 생성자/참여자/허가 운영자의 캐릭터 초대.
- `POST /api/roleplay/messages`: 메시지 생성/수정. 신규 전송은 request_id 필수, 수정은 id·revision 필수.
- `DELETE /api/roleplay/messages/:id`, `DELETE /api/roleplay/scenes/:id`: X-Revision 헤더를 검사한 소프트 삭제.
- `POST /api/roleplay/upload?scene=…`: 기존 이미지 변환 함수를 거친 WebP/GIF 업로드. 인증된 `/api/files/:path`에서도 장면 권한을 검사한다.
- `GET/POST /api/roleplay/preferences`: 역극 알림 설정.
- `POST /api/roleplay/read`: message_id를 기준으로 해당 장면/대화 읽음 기록.
- `GET /api/roleplay/export?scene=…` 또는 `?thread=…`: 텍스트 내보내기. `format=html`, `ooc=hide` 옵션 지원.


이미 개발 서버가 실행 중이면 같은 서버를 계속 사용한다. 개발 DB는 `.wrangler/local-development`이고 운영 D1과 분리된다. `http://localhost:8090/#/roleplay`에서 로컬 로그인 후 사용한다.

## Cloudflare 배포

2026-11-17 사용자 승인 후 운영 반영을 완료했다. `0004_character_questions.sql`, `0005_roleplay.sql`을 운영 D1에 적용하고 `dragonage-circle-api` Worker 및 `gwaren-tower` Pages를 배포했다. 두 마이그레이션은 CREATE TABLE/CREATE INDEX만 포함한다. 적용 전후 집계는 회원 4, 캐릭터 7, 게시글 11, 댓글 8, 관계 12, 호감도 7, 이미지 14건으로 동일하다. 운영 역극 장면·메시지는 새 테이블의 0건으로 시작하며 로컬 테스트 데이터는 운영으로 옮기지 않았다.

운영 주소: https://gwaren-tower.pages.dev/#/roleplay

Worker 버전: `4e1a198b-b96f-4751-86ac-6add28b67002`. Pages 배포: `e3794879`. 운영 홈페이지 200 응답, 운영 app 번들과 로컬 빌드의 SHA-256 일치, 비로그인 `/api/me` 및 `/api/roleplay/sync`의 401 차단을 확인했다. 최신 관계도 드롭다운 제거·컨트롤 한 줄 배치도 함께 반영했다.

로컬 검증 후 다음 순서를 따른다. 사이트와 API가 신규 테이블을 참조하므로 DB 추가가 먼저다.

```powershell
npm.cmd run db:remote
npm.cmd run worker:deploy
npm.cmd run build
npm.cmd run pages:deploy
```

운영 대상은 기존 `circle-alliance` D1, `dragonage-circle-api` Worker, `gwaren-tower` Pages이며 기존 서비스 바인딩·인증 시크릿·R2를 유지한다. 원본 GM 아카이빙 사이트와 `upstream/`은 변경하지 않는다. DB 추가는 역극 테이블/인덱스만 생성한다.

기존 백업 스냅샷과 이미지 원본 백업에 역극을 포함했다. 별도 `역극/` 분류 폴더도 생성하도록 로컬 백업 도구와 Apps Script 소스를 갱신했다. 운영 Apps Script의 표시용 분류 폴더까지 바꾸려면 `google-apps-script/Code.gs`를 기존 Apps Script 프로젝트에 반영해야 한다. 기존 실행 중인 백업도 전체 snapshot.json에는 신규 역극 테이블을 포함하므로 원본 보존은 유지된다.

## 범위와 제한

이메일 알림, 관계/호감도 자동 변경, 활동 점수, 출석 보상, 새 유료 실시간 서비스는 추가하지 않았다. 텍스트/HTML 내보내기는 대화 내용용이며 첨부 이미지 원본은 기존 전체 백업에서 보존한다. 관계 페이지는 공통 참여 기록을 자동 표시하며 별도 수동 연결 UI는 추가하지 않았다.

소규모 동맹의 검색은 서버에서 열람이 허용된 텍스트 기록을 커서로 동기화한 후 기기에서 필터링한다. 대규모 기록을 위한 서버 전문 검색/검색 인덱스는 후속 최적화 대상이다. 이미지와 수정 이력은 장기 보존을 위해 자동으로 지우지 않는다.
