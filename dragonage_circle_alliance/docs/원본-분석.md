# 원본 분석 및 분리 기준

분석 대상은 현재 작업 공간 `dragonage_gm_note_v2`의 실제 웹사이트입니다. Foundry VTT 모듈이 아닙니다.
요청문에 나온 `드에모듈` 이름의 폴더는 현재 작업 공간에 없었으며, README·라우터·서비스·UI가 요청의 아카이빙 기능에 부합하는 사이트임을 확인했습니다.

## 확인한 구조

- Vue 3, Vue Router 4 hash history, Vuex 4, Vue CLI 5.
- Supabase Postgres/Auth/Storage/RLS/RPC/Edge Functions. 플레이어 PIN과 GM 인증을 별도로 운용.
- 캐릭터는 `users` 계열 및 팀·캠페인과 연동하며 플레이어 프로필 변경에 GM 승인을 요구.
- `CharactersView`, `CharacterDetailView`, `FreeBoardView`, `GalleryView`, `NpcFeedbackView` 및 관련 SQL에 프로필·게시글·이미지·NPC 별점·댓글 구현.
- 시나리오 진행·팀 권한·NPC 공개 범위·알림·이미지 Drive 이관·Google 백업 작업이 함께 존재.
- 원본 배포 명령은 Vue CLI 정적 빌드 후 gh-pages이며 경로는 `/GM-note/`.
- 원격 DB 용량·실제 요금제·SQL 적용 여부는 계정 미접속으로 확인하지 않았음. 원본 키를 읽거나 복사하지 않았음.

## A. 유지·재사용

원본 App.vue의 서체, DashboardLayout.vue의 공통 CSS와 레이아웃 CSS를 `src/legacy.css`로 추출.
따뜻한 종이색·먹색 사이드바·장밋빛 버튼·카드·폼·모바일 스타일을 유지.
원본 `src`, `public`, `supabase`, package 파일과 README를 `upstream/`에 보존.

## B. 변경

팀/PIN 단일 캐릭터 권한을 Google 이메일 등록제·여러 캐릭터 소유로 분리.
NPC 별점 대신 별도 방향별 호감도를 만들고, 댓글에 author owner ID와 character ID를 함께 기록.
시나리오·팀 종속 로직이 결합된 컴포넌트와 DB 서비스는 그대로 연결하면 기존 데이터·권한을 건드릴 수 있어 동맹용 서비스로 분리.
사용자의 후속 요청에 따라 새 사이트 저장소만 Supabase에서 D1/R2로 변경하고 원본 Supabase는 보존.
Supabase용 신규 운영 스키마·접속 설정은 새 앱에서 사용하지 않음.

## C. 새 사이트에서 제외

시나리오, 캠페인, 팀 진행률, NPC 진행 공개, PIN 로그인, 출석·랭킹·필수 이벤트.
원본 코드·데이터·시나리오 테이블에는 삭제·변경 작업을 수행하지 않음.

## 새 파일 구성

`src/Shell.vue`: 동맹 내비게이션·프로필·게시판·운영 UI.
`src/RelationshipGraph.vue`: Cytoscape 관계도. `CommentsPanel.vue`, `MentionText.vue`, `Portrait.vue`: 댓글·멘션·이미지.
`worker/`: OAuth·세션·API·소유자·승인 검사. `migrations/`: 별도 D1 스키마.
`functions/api/`: Pages → Worker 서비스 바인딩 프록시.
`google-apps-script/`: Drive 백업과 Sheets 기록. `scripts/`: 백업·검증·복구 CLI. `tests/`: 권한과 데이터 보존 검증.
