# Google Drive 매일 자동 백업

매일 한국 시간 오전 3~4시에 날짜별 백업 폴더를 만듭니다. PC를 꺼도 Apps Script가 실행합니다.
실제 시간은 Google 시간 기반 트리거 정책에 따라 이 범위 내에서 정해집니다.

백업 내용: 회원, 캐릭터, 설정과 비밀 설정, 호감도, 관계, 게시글, 댓글, 이미지 메타데이터,
업로드 이미지 원본, 수정·소프트 삭제 이력, 백업 실행 기록.
로그인 세션과 OAuth 임시 상태, 운영 비밀키는 백업하지 않습니다.

## 한 번만 하는 Google 설정

1. https://script.google.com 에서 새 프로젝트를 만들고 이름을 `Gwaren Tower 매일 백업`으로 설정합니다.
2. `google-apps-script/Code.gs`를 코드 편집기에 붙여넣고 저장합니다.
3. 프로젝트 설정에서 `appsscript.json 매니페스트 파일 표시`를 켜고, 저장소의 `google-apps-script/appsscript.json` 내용으로 적용합니다.
4. 프로젝트 설정 > 스크립트 속성에 `BACKUP_TOKEN`을 추가합니다. 값은 Git에서 제외된 `.backup.local.env`의 BACKUP_TOKEN 값입니다.
5. 실행할 함수로 `setupBackup`을 선택하고 실행합니다. 본인의 Google 계정으로 Drive·Sheets·외부 요청·트리거 권한을 승인합니다.
6. 실행 로그의 Drive 폴더와 기록 시트를 확인합니다. 최초 백업 성공 행이 생기고 트리거에 `startBackup`이 등록되어야 합니다.

SITE_URL, DRIVE_FOLDER_ID, SPREADSHEET_ID는 setupBackup이 자동 설정합니다.
기존에 원하는 백업 폴더가 있다면 setupBackup 실행 전에 DRIVE_FOLDER_ID 속성을 직접 지정할 수 있습니다.
같은 프로젝트에서 setupBackup을 다시 실행하면 기존 폴더·시트를 재사용하고 일일 트리거가 중복되지 않게 합니다.
이 스크립트는 웹 앱으로 배포하지 않습니다.

## 검증과 복구

날짜별 폴더마다 snapshot.json, manifest.json, 이미지 원본 파일이 생성됩니다.
DB 파일과 이미지마다 SHA-256을 검사합니다. 모든 파일 검증에 성공한 경우에만 manifest.complete=true로 기록합니다.
실패한 백업 폴더 이름은 -PARTIAL을 유지하며 성공한 이전 백업은 삭제하지 않습니다.
이미지가 많으면 다음 실행으로 이어받아 Apps Script 실행 제한에 대응합니다.

완료된 백업 폴더를 다운로드하고 BACKUP_DIR 환경변수로 폴더를 지정한 뒤 `npm run restore`로 검증할 수 있습니다.
실제 복구 절차는 `docs/배포와-백업.md`를 참고하세요. 운영 DB를 덮어쓰기 전에 별도 새 DB에서 복구를 확인하세요.
Google Drive 동기화 PC 폴더의 1회 백업은 Google 클라우드에 업로드 완료됐는지도 Drive 앱에서 확인해야 합니다.
