# 배포와 Google Drive 백업

## 1. Cloudflare 리소스

Cloudflare 계정에서 R2를 활성화한 뒤 새 D1·비공개 R2를 만듭니다. 원본 사이트 자원을 재사용하지 않습니다.

```powershell
npx wrangler login
npx wrangler d1 create circle-alliance
npx wrangler r2 bucket create dragonage-circle-private
```

`worker/wrangler.toml`의 `database_id`를 새 D1 ID로 바꾸고 `SITE_ORIGIN`을 실제 Pages 주소로 설정합니다.
R2 버킷은 public access·r2.dev·공개 custom domain을 켜지 않습니다.
`npm run db:remote`로 마이그레이션을 적용합니다. 기존 DB에는 실행하지 마세요.

## 2. Google OAuth

Google Cloud Console에서 OAuth 동의 화면과 Web application 클라이언트를 만듭니다.
리디렉션 URI는 `https://실제-pages-주소/api/auth/callback`입니다.
로컬 테스트용 URI는 `http://localhost:8090/api/auth/callback`을 별도로 등록합니다.
앱이 Testing 상태면 로그인할 Google 계정을 테스트 사용자에도 추가합니다.
Google Drive 접근 권한은 사이트 로그인에 요구하지 않고, `openid email profile`만 사용합니다.

아래 시크릿을 Worker에 등록합니다.

```powershell
npx wrangler secret put --config worker/wrangler.toml GOOGLE_CLIENT_ID
npx wrangler secret put --config worker/wrangler.toml GOOGLE_CLIENT_SECRET
npx wrangler secret put --config worker/wrangler.toml BOOTSTRAP_ADMIN_EMAIL
npx wrangler secret put --config worker/wrangler.toml BACKUP_TOKEN
npx wrangler secret put --config worker/wrangler.toml RESTORE_TOKEN
```

BACKUP_TOKEN과 RESTORE_TOKEN은 서로 다른 충분히 긴 무작위 값으로 지정합니다.
백업 토큰은 읽기·백업 상태 기록만 허용하며 복구 쓰기는 별도 복구 토큰이 필요합니다.
처음 관리자 이메일로 로그인하면 관리자 계정이 만들어집니다. 이후 운영 관리 화면에서 회원 Google 이메일을 등록하세요.
회원 등록은 이메일 허용 목록 추가이며 자동 초대 메일은 발송하지 않습니다.

## 3. Worker와 Pages 배포

```powershell
npm install
npm test
npm run build
npm run worker:deploy
npx wrangler pages project create dragonage-circle-alliance --production-branch main
npx wrangler pages deploy dist --project-name dragonage-circle-alliance
```

Pages 설정 > Bindings에서 Service binding `API`를 `dragonage-circle-api` Worker에 연결합니다.
루트 `wrangler.toml`이 Pages 전용 설정이며 `API` 서비스 바인딩을 선언합니다. Worker와 DB 명령은 별도 `worker/wrangler.toml`을 사용하도록 npm 스크립트에 설정되어 있습니다.
Git 배포 시 빌드 명령 `npm run build`, 산출물 `dist`, 루트 `functions/`를 포함합니다.
Pages 미리보기 주소는 기본적으로 허용하지 않습니다. 로그인·쓰기 검증의 Origin은 운영 주소 하나에 맞춰져 있습니다.
정적 앱 껍데기는 공개되어도 데이터·프로필·게시글·이미지는 Worker 세션 검증 전 반환되지 않습니다.

## 4. 로컬 검증

`.dev.vars.example`을 `worker/.dev.vars`로 복사하고 Google OAuth 클라이언트와 관리자 이메일을 입력합니다.
`worker/wrangler.toml` SITE_ORIGIN을 `http://localhost:8090`으로 둡니다.
`npm run db:local` 이후 터미널 1에서 `npm run worker:dev`, 터미널 2에서 `npm run serve`를 실행합니다.
로컬 D1/R2는 `.wrangler/`에만 저장되어 운영 자원에 영향을 주지 않습니다.

## 5. Google Sheets / Apps Script / Drive 정기 백업

1. 개인 Google Drive에 공유하지 않은 백업 폴더를 만듭니다.
2. 새 Google Sheets를 만들고 확장 프로그램 → Apps Script를 엽니다.
3. `google-apps-script/Code.gs`를 붙여넣습니다. 프로젝트 설정에서 매니페스트를 표시하고 `appsscript.json` 내용도 적용합니다.
4. 스크립트 속성에 `SITE_URL`(Pages 운영 주소), `BACKUP_TOKEN`, `DRIVE_FOLDER_ID`, `SPREADSHEET_ID`를 저장합니다. 시트 셀·공개 URL·프런트 코드에는 토큰을 넣지 않습니다.
5. `startBackup`을 수동 실행해 권한을 승인합니다. Drive에 snapshot.json·manifest.json·이미지가 생성되고 Sheets `백업 기록`에 성공 행이 생기는지 확인합니다.
6. `setupBackup` 또는 `installBackupTrigger`를 실행하면 매일 한국 시간 오전 3~4시에 실행합니다. Apps Script 트리거의 실제 실행 시각은 Google에서 정합니다.

DB는 D1 batch로 한 시점의 스냅샷을 읽고, 업로드 메타데이터와 이미지 원본은 별도 파일로 보관합니다.
이미지는 SHA-256과 크기를 확인한 뒤 성공으로 기록합니다. 실패한 폴더는 `-PARTIAL` 이름을 유지합니다.
약 220초마다 진행 위치를 저장하고 이어받기 트리거를 만들어 Apps Script 실행 시간 제한에 대응합니다.
실패한 작업은 `continueBackup`을 다시 실행하면 이어받습니다. 원인이 해결되기 전까지 불완전한 백업을 성공으로 표시하지 않습니다.
카테고리별 최신 백업과 최근 3일의 날짜별 복구본을 보관합니다. 새 백업 검증 성공 후 기간이 지난 관리 대상 복구본만 Drive 휴지통으로 이동합니다. 상세 구조는 `docs/구글드라이브-매일백업.md`를 참고하세요. Drive 용량은 직접 확인해야 합니다.
시트나 스크립트 편집 권한이 있는 사람은 토큰에 접근할 수 있으므로 본인만 편집하도록 유지하세요.

## 6. 로컬 백업 및 복구

Node.js 22 이상에서 환경변수 SITE_URL·BACKUP_TOKEN을 설정하고 `npm run backup`을 실행하면 DB와 이미지 검증을 포함한 폴더가 생성됩니다.
Drive에서 완성된 백업 폴더를 다운로드하고 압축을 푼 뒤 `BACKUP_DIR`을 지정합니다.

```powershell
$env:BACKUP_DIR='D:\내백업\circle-2026-11-16'
npm run restore
```

위 명령은 DB 파일과 이미지 해시만 검증합니다. 실제 복구는 별도 새 D1/R2에 먼저 마이그레이션을 적용하고, SITE_URL을 복구 대상 서버로, RESTORE_TOKEN을 복구 대상의 시크릿으로 설정한 다음 실행합니다.

```powershell
npm run restore -- --apply
```

원본 이미지를 먼저 복원하고 D1 데이터는 단일 batch로 복구합니다. 중간 DB 오류는 전체 DB batch를 롤백합니다.
기존 동명 이미지의 해시가 다르면 중단합니다. 기존 DB 행은 백업의 동일 ID로 덮어쓰므로 반드시 새 복구 자원에서 검증하세요.
복구는 백업에 없는 현재 행을 삭제하지 않는 병합 방식입니다. 완전한 과거 시점 복구는 새 빈 DB에서 수행하세요.
세션은 백업하지 않고 복구 후 기존 세션을 폐기합니다. Google 계정 ID와 이메일은 회원 데이터에 포함되어 같은 계정으로 다시 로그인할 수 있습니다.
변경 기록은 운영 화면에서 개별 복구할 수도 있습니다.

## 7. 운영 확인과 비용

무료 사용량은 보장하지 않습니다. D1/R2/Workers와 Drive/Apps Script는 계정의 현재 한도를 확인하세요.
운영 화면은 활성 이미지 메타데이터 용량을 보여줍니다. 삭제·고아 업로드를 포함한 전체 R2 저장량과 D1 사용량은 Cloudflare 대시보드에서 확인합니다.
회원 전체 조회/이미지 다운로드는 최초 로딩·수동 갱신·60초 폴링 시 발생하므로 소규모 운영을 전제로 합니다.
이미지는 공개 URL이나 만료 전 접근 가능한 서명 URL 대신, 매 요청 로그인 확인 후 브라우저 Blob으로 표시합니다.
이미 내려받은 파일이나 화면 캡처까지 회수할 수는 없습니다.
